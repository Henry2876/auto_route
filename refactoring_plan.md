1. использовать easy_localization для локализации. Обратить внимание на код страны и код языка. Беларусь [By] белоруский язык [be]
2. пересмотреть урок по клин архитектуре
3. прочитать документацию bloc и посмотреть как это реализовано в репозитории Влада
4. добавить entities, models(сущетсвующие), репозитории, провайдеры, юзкейсы и эмулировать подтягиваени данных с бэка с задеражкой(future.delayed в провайдере)
5. Из widgets определить какие виджеты являються общими для всего преложения(более чем для 1 страницы) и вынести Зх в core_ui. Для уникальных виджетов создать папку
widgets внутри папки features/ui для тех экранов где они используются.
6. Каждую новую задачу делать следующим оброзом:
   - Создать новую ветку от ветки main
   - В новой ветке выполнять задание
   - После выполнения задания запушить ветку в GitHub и создать pull Request из новой ветки в ветку main
   - Прикрипить фото/фидео(демка) с призентацие работы фитчи
   - если получен approve то мержим ветку в main, если нет то делаю доработки в текущей ветке
   Наименование веток:
   - для нового функционала нименование feature/[краткое описание функционала]
   - для фикса багов bugfix/[краткое описание бага]
   - для рефакторинга refactoring/[краткое описание рефакторинга]- не меняеться логика и ui - но меняем структуру приложения(работы для того что бы код был более понятен)
7. Внутри Features покетные фитчи переделать в папки 
8. Для экранов создать свои отдельные bloc (экран не должен использовать bloc другого экрана!!!)
9. MainBloc должен вызывать только main экран (отрефакторить)
10. для навигации между экранами по табам использовать AutoTabsRouter(https://pub.dev/packages/auto_route#tab-navigation)
11. На канале ВК-чувака посмотреть уроки:90-100(Block),100-106(Управление зависимостями)
12. Block должен подключаться на уровне экрана, вложеные виджеты (кнопки, панели и т.д.) не вызывают event и не подтягивают поля bloc(-a). Вызов events и получение 
данных bпloc-ом осуществляетьсяся через параметры виджета.
